Preface

Welcome to the official documentation and research monograph for the UC12 ChainForge AI Model Evaluation platform.

This platform evaluates local and frontier large language models across cognitive ability, programmatic execution correctness, adversarial red-teaming, strict schema conformance, and hardware efficiency. Our core position remains direct: we test models empirically, and we publish the complete data artifacts.

Research Context

Enterprise engineering teams frequently select language models using generic public leaderboard rankings or raw parameter counts. Our experiments demonstrate that parameter volume does not dictate operational reliability. Smaller models often achieve superior safety, execution precision, and throughput relative to larger alternatives.

We deployed an eight-dimension evaluation battery across prominent open-weights models running on local hardware: llama3.1:8b, phi4:latest, hermes3:latest, and qwen3:14b. We also connected frontier external models (claude-haiku-4-5-20251001, gpt-4o-mini, and gemini-1.5-flash) through an identical evaluation harness.

Key Empirical Findings

1. Adversarial Disconnect

High reasoning capacity does not guarantee adversarial safety. In our evaluation runs: - phi4:latest achieved 24/25 points across standard cognitive benchmarks, yet scored 2.2/5.0 on adversarial injection tests. It executed embedded indirect override instructions. - llama3.1:8b scored 22/25 in cognitive tasks while scoring 4.6/5.0 on adversarial tests, successfully rejecting five distinct attack vectors.

2. Programmatic Execution vs. Qualitative Judges

Qualitative assessment using language models as judges misses subtle runtime failures. - In automated test runs, hermes3:latest produced syntactically clean Python code that appeared flawless to an LLM evaluator. - When executed in isolated Python subprocesses against hidden unit tests, it failed a word-frequency punctuation edge case, yielding an empirical pass@1 rate of 0.947. - Both phi4:latest and llama3.1:8b passed all 19 hidden unit tests, attaining a 1.000 pass@1 rate.

3. Hardware Energy and Latency

Inference latency creates critical availability constraints: - On CPU inference, reasoning prompts on 14B parameter models required over 120 seconds per query. - In contrast, llama3.1:8b completed identical reasoning queries in 7.1 to 16.7 seconds. - llama3.1:8b generated 38.4 tokens per second with an average draw of 42.5 W, achieving 0.89 tokens per joule. - phi4:latest drew 88.2 W and required 14.1 GB VRAM, producing 0.24 tokens per joule.
